# Meta Retrospective — After Mao Selected Works Volume I

> Scope: what the **research process itself** learned while completing V1-001—V1-018.  
> This is not a summary of Mao's philosophy. It is evidence about the evolving Praxis Engine research method.

## 1. Initial research assumption that failed

The project began with an attractive target architecture:

```text
investigation
-> principal contradiction / bottleneck
-> strategy
-> limited practice
-> feedback
-> correction
```

Volume I showed that this was too neat.

The first major correction came from V1-003: some systems are not single-bottleneck systems but conjunctions of multiple conditions. Later economic and military texts showed further structures:

- dependency chains;
- supporting subsystems;
- local decisive points inside globally constrained systems;
- stage-dependent priority shifts;
- feedback systems.

Meta lesson:

> A research framework must not force every new case to instantiate the abstractions that motivated the project.

## 2. Protocol evolution validated by use

The six-pass protocol introduced after V1-002 proved useful because it repeatedly prevented premature abstraction:

```text
0 historical frame
1 source/argument reconstruction
2 evidence audit
3 reasoning reconstruction
4 adversarial reading
5 article-local candidate mechanisms
6 cross-article update
```

Observed benefits:

- philosophical vocabulary no longer automatically overrides operational structure;
- author inference is separated from observation;
- later editorial framing is separated from contemporaneous evidence;
- counterexamples can downgrade patterns;
- different error layers become visible.

Cost:

- more bookkeeping;
- risk of duplicating article card and evidence ledger;
- risk of methodology ceremony becoming an end in itself.

Current judgment: retain the protocol, but do not add a new mandatory field unless a real article exposes a repeated failure.

## 3. The Agent should learn on two loops

Object loop:

```text
article/problem
-> evidence
-> interpretation
-> output
```

Meta loop:

```text
research behavior
-> detect systematic failure
-> change protocol
-> test on next tasks
-> retain / modify / rollback
```

Crucially:

```text
more protocol != better protocol
```

Method changes themselves are hypotheses.

## 4. Representation is upstream of evidence collection

Volume I exposed that even good field investigation can be constrained by the ontology used to ask questions.

Example structure:

```text
initial classification schema
-> determines what is recorded
-> evidence appears to validate schema
-> action uses classification
```

The system must therefore distinguish:

- **task environment** — what exists outside the model;
- **problem representation** — what variables/relations the agent currently sees;
- **observation plan** — what evidence the representation causes it to collect.

Representation should be revisable when evidence repeatedly falls outside the schema.

## 5. Evidence and theory need an explicit middle layer

One of the strongest corpus patterns is that raw evidence does not directly determine action.

Praxis Engine should preserve:

```text
observation
-> source/quality audit
-> relational synthesis
-> competing explanation
-> belief / judgment
```

This is a safeguard against both:

- book/theory-first dogmatism;
- fragmentary experience-first empiricism.

## 6. Belief update and action commitment are different control problems

Volume I supports separating:

```text
OPEN EPISTEMIC MODE
competing evidence / disagreement / model revision

COMMITMENT GATE

EXECUTION MODE
coordination / responsibility / implementation

VALIDATION GATE

REOPEN IF NECESSARY
```

Agent implication:

A plausible hypothesis must not become an external modification merely because the reasoning path is coherent.

Conversely, after a reversible commitment is made, endless reconsideration can destroy coordinated execution.

The boundary needs to be explicit and risk-sensitive.

## 7. Practice-as-learning requires a risk gate

Historical revolutionary texts can normalize high-cost action as a source of knowledge.

A modern Agent cannot transfer this literally.

Before action-as-experiment:

```text
estimate reversibility
estimate blast radius
estimate affected rights/interests
estimate ability to observe outcome
prefer lower-risk discriminating test
```

High-risk or irreversible actions require stronger pre-action evidence and human authority.

## 8. Error localization is more important than generic reflection

The revision ledger revealed multiple failure layers:

- observation/factual;
- ontology/representation;
- causal model;
- stage;
- actor model;
- parameter/timing;
- policy design;
- organizational design;
- metric;
- execution;
- argument sufficiency;
- scope/boundary;
- environment change.

Therefore a generic Agent instruction such as `reflect and improve` is under-specified.

Better control question:

> What exact layer is contradicted by the new evidence, and what is the smallest revision that resolves that mismatch?

## 9. No monotonic self-improvement assumption

`实践论`'s recursive cycle is useful, but Volume I also shows that repeated practice can reinforce error.

Agent learning loop should therefore be modeled as:

```text
iteration
-> possible improvement
   or overfit
   or drift
   or confirmation loop
   or newly exposed unknown
```

Improvement requires evidence quality, hypothesis competition, validation, scope control and willingness to downgrade.

## 10. Variant/source evolution matters for Agent research

V1-016, V1-017 and V1-018 showed that canonical/edited texts can materially alter apparent reasoning structure.

Meta implication:

When distilling a durable method from evolving artifacts:

```text
current canonical artifact
!=
original decision-time artifact
```

Do not use later polished documentation to infer what the agent/person actually knew at the earlier decision point.

This applies beyond historical texts to:

- edited incident reports;
- postmortems;
- final code after debugging;
- polished design docs;
- retrospective summaries.

## 11. Relationship to AgentRecord

AgentRecord is an external long-term authority for Agent-level mechanisms.

Current Volume-I findings overlap strongly with AgentRecord themes such as:

- problem representation;
- belief/evidence update;
- commitment;
- validation;
- experience retention.

However, overlap is not sufficient reason to write back.

Write-back threshold remains:

```text
Praxis Engine evidence
-> materially changes an AgentRecord judgment,
   evidence strength,
   boundary,
   or practical action
-> then update AgentRecord with immutable evidence pointer
```

At the end of Volume I, no forced AgentRecord update is required. Volume II should test whether the newly reconstructed controls survive a different historical regime and larger organizational context.

## 12. Meta hypotheses carried into Volume II

- M1: representation errors are upstream of search/evidence errors;
- M2: evidence acquisition and synthesis need separate controls;
- M3: belief and commitment require separate gates;
- M4: risk/reversibility must bound action-as-learning;
- M5: correction should localize the failed layer;
- M6: methodology itself should change only after repeated task evidence;
- M7: no self-improvement loop should assume monotonic progress;
- M8: canonical retrospective artifacts require decision-time source audit when available.

These are **not final Agent laws**. Volume II is a new test set.
