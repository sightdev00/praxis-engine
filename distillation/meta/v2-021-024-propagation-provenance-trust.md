## M-08 — Organizational propagation is not evidence replication

V2-021 turns earlier international analyses into a Central Committee decision. This raises adoption/commitment but does not provide independent evidence for the upstream claims.

### Control

Cross-text synthesis must distinguish:

```text
independent evidence repetition
from
same model copied into a new organizational artifact
```

Record propagation value separately:

- `epistemic support`: does new evidence increase confidence?
- `commitment/adoption`: did the organization begin acting on the claim?

A claim can have low epistemic confidence and high organizational commitment at the same time. That combination is particularly important for risk analysis.

## M-09 — Authorship/provenance is part of textual confidence

The editorial note for V2-023 states:

```text
Chapter I -> drafted by several Yan'an comrades, revised by Mao
Chapter II -> written by Mao
Chapter III -> planned but unfinished
```

A corpus-level label such as “Mao Selected Works” therefore does not imply equal direct authorship for every proposition.

### New provenance fields

For important source claims, record where relevant:

```text
corpus item
section/chapter
original author / drafter
editor/reviser
speech recorder / compiler
later editorial transformation
confidence in attribution
```

### Synthesis rule

Do not count a mechanism as repeated direct author evidence when:

- the relevant section was drafted by others and only revised;
- two texts copy from the same prior decision/report;
- an editor later inserted framing that resembles the author's later theory.

This does not make collaborative text unusable. It changes what the text can support.

## M-10 — Security screening must model false positives as well as false negatives

V2-022 is unusually explicit that suspected hostile entrants should be handled with `真凭实据`, while also preventing malicious actors from framing good participants.

This matters because security systems often optimize only:

```text
prevent bad actor entering
```

and omit:

```text
avoid excluding or punishing good actor
```

### Research/Agent transfer hypothesis

For any trust or access classifier, ask:

```text
false acceptance cost?
false rejection cost?
what evidence threshold?
what appeal/review route?
what lower-permission collaboration mode exists?
```

This remains a Praxis candidate until tested against modern Agent/plugin/tool-permission cases.

## M-11 — Trust should be layered and time-bounded

V2-024 first uses a sound heuristic — actual costly support over self-description — then promotes it into a fixed friend/system identity.

Combined with V2-019, the research lesson is:

```text
current cooperation value
current evidence of alignment
trust level
dependency level
long-horizon identity
```

should not be one field.

### Control

Important reliability judgments should eventually record:

- evidence basis;
- validity horizon;
- change triggers;
- dependency exposure;
- revalidation date/condition.

---

## M-12 — Problem representations need cascade-risk audit

V2-023 makes a clean chain:

```text
social nature
-> contradiction
-> object/task
-> forces
-> stage/nature
-> future transition
```

The clarity is valuable, but one upstream ontology error can make every downstream conclusion internally consistent and jointly wrong.

### Control

For high-impact reasoning chains, identify:

```text
upstream assumptions
which downstream decisions inherit each assumption
what observation can independently challenge the upstream model
```

This complements, rather than replaces, ordinary claim-level evidence auditing.

---

## Protocol status

Adopt immediately at research-control level:

- distinguish propagation from replication;
- record source provenance when attribution is mixed;
- preserve false-positive and false-negative costs in security analysis;
- time-bound trust/reliability judgments;
- audit representation cascade risk.

The core six-pass workflow remains unchanged.
