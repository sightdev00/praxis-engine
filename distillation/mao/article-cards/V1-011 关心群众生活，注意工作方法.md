1. 群众生活；

目标已经明确

# Pass 1 — Source / argument reconstruction

## 1.1 中心目标不能绕过参与者自身的现实需求

文章认为战争依赖群众，因此只要求群众承担战争任务、却不处理其现实生活问题，会破坏动员基础。

具体需求包括：

- 土地与劳动；
- 柴米油盐；
- 衣食住房；
- 疾病卫生；
- 婚姻；
- 教育；
- 桥梁等日常公共问题。

关系链被写成：

```text
解决现实生活问题
-> 群众认为组织代表其利益
-> 信任/拥护增强
-> 更愿承担更高层政治与战争任务
```

## 1.2 汀州与长冈/才溪形成准比较

### 汀州案例

政府几次会议只讨论：

- 扩大红军；
- 动员运输队；

而忽略：

- 无柴；
- 盐短缺；
- 无房；
- 缺米、米贵。

结果：

- 一百多代表后来不愿参会；
- 会议召集困难；
- 红军与运输动员成绩也少。

### 长冈/才溪案例

乡政府处理：

- 火灾住房援助；
- 无饭者救济；
- 夏荒调米；
- 其它实际生活问题。

同时红军动员与公债等任务成绩显著。

文章据此把“关心生活”与更强动员联系起来。

## 1.3 需求必须进入正式工作闭环

不是泛泛“关心”，而是：

```text
提到议事日程
-> 讨论
-> 决定
-> 实行
-> 检查
```

这和 V1-008 的讨论—督促—检查形成同一执行结构。

## 1.4 第二个问题：任务声明不等于执行方案

文章用“过河需要桥或船”比喻：

```text
task
without
method
-> cannot reach outcome
```

因此扩大红军、查田、经济、教育等任务都必须同时研究：

- 实际具体方法；
- 如何反官僚主义；
- 如何反命令主义；
- 如何说服和组织。

## 1.5 先进案例被用作可复制学习资源

文章不只表扬长冈、才溪、兴国、赣东北等地，而要求：

```text
先进地方继续前进
+ 帮助工作薄弱地方
-> 复制更多可运行阵地
```

这是一种 case-based diffusion 思路。

但“模范”是否具有可迁移因果机制，必须进一步拆解，不能只复制表面做法。

# Pass 2 — Evidence audit summary

详细见 `../evidence/v1-011/evidence-ledger.md`。

本文最有价值的不是宏观理论，而是两个不同工作方法案例的行为结果：

- 汀州：忽视实际需求 -> 代表不再参会 -> 核心动员任务表现差；
- 长冈/才溪：解决实际需求 -> 高动员与公债等成绩。

但它仍不是控制实验：地区条件、干部能力、组织基础、军事压力等都可能不同。

# Pass 3 — Reasoning reconstruction

## R1 — Connect mission demands to participant value/needs

一个系统不能只向参与者索取目标贡献，而不给他们能感知的现实价值。

## R2 — Compare operating methods under a shared nominal goal

不同地方都要战争动员，但工作方法差异与结果差异被拿来比较。

## R3 — Turn concern into an execution loop

议题化、决策、实施、检查，而非态度表达。

## R4 — Separate objective specification from method design

知道“要做什么”不等于知道“怎么做到”。

## R5 — Learn from working local cases, then scale mechanisms

优秀地方成为组织学习样本。

# Pass 4 — Adversarial reading

## A1 — “解决生活 -> 支持战争”的因果链可能混杂

模范乡也可能同时拥有：

- 更强干部；
- 更成熟组织；
- 不同敌情；
- 不同人口结构；
- 不同经济条件。

这些共同因素可能同时解释生活工作和动员成绩。

## A2 — 关心生活被工具化为政治动员手段

现代迁移必须区分：

```text
participant welfare as intrinsic constraint/value
vs
participant welfare only as instrument for output
```

否则容易变成操纵性“关心”。

## A3 — 代表不来参会可能不只因为生活问题未解决

需要更多一手访谈才能确认原因。

## A4 — 模范复制存在 survivorship bias

成功地区被选为案例，不代表复制其显性做法就能在其它地方复现结果。

## A5 — “群众必定拥护”等确定性语言超过证据

需求响应通常提高信任概率，但不能保证支持，因为参与者还有价值、身份、风险和替代选择。

# Pass 6 — Cross-article update summary

## P2 strengthened — implementation method is causal

V1-008 命令主义公债/合作社不能巩固；V1-011 对比不同工作方法与动员结果。

“任务正确”不够，执行方法会改变系统反应，已跨经济与群众动员情境。

## P2 — system objective requires supporting participant conditions

V1-008：经济与生活条件是战争能力的支撑。  
V1-011：群众生活需求直接进入动员基础。

这进一步限制了“中心任务”的含义：

```text
central objective
cannot erase
conditions required for the agents/participants who realize it
```

## Emerging workflow pattern

V1-008 / V1-011 都出现：

```text
agenda
-> discuss
-> decide
-> execute
-> inspect
```

这是值得继续追踪的组织执行闭环，目前可标 `P1/P2 candidate`。

## First-pass takeaway

这篇把领导问题压缩成了一个非常实际的结构：

```text
明确目标
-> 识别实现目标所依赖的人
-> 处理他们真实且具体的问题
-> 把问题纳入议事/决定/实行/检查闭环
-> 为每项任务设计具体方法
-> 比较成功与失败地方的工作机制
-> 再扩散经过理解的机制
```

对 Praxis Engine 的重要修正是：**“中心目标”不能把参与者降为纯资源。系统若依赖人的长期参与，其需求、信任和承受能力本身就是系统状态变量。**
